Autism-Friendly Web Design — Assignment Explanation

Two websites · Rule-by-rule breakdown · GitHub Pages setup guide

Overview

This document explains two websites created for the universal design assignment. Both sites cover the same topic — a reading platform called Leafwell. One site follows all autism-friendly design guidelines from the lecture materials. The other site deliberately breaks every rule to demonstrate the contrast.

✓ Good site: Leafwell (good/index.html)

  • Calm, muted colour palette
  • Readable 18px body text, 1.75 line-height
  • No autoplay, no animations
  • Persistent dark mode, font-size, motion controls
  • Consistent navigation, icon + text labels
  • Plain, literal language — no idioms
  • Visible keyboard focus indicators
  • Skip navigation link

✗ Bad site: Mega Deal Zone (bad/index.html)

  • Neon clashing colours, pure white background
  • 9px body text, 1.0 line-height
  • Constant flashing, spinning, bouncing animations
  • Autoplay audio and fake video
  • Pop-up appears 3 seconds after load
  • Icon-only navigation buttons
  • Colour-only signals (no text or icons)
  • Panic-inducing countdown timers
  • Sarcastic, idiomatic language
  • No focus indicators

Good site — rules followed

The guidelines are taken directly from the lecture slides (PDF) and from the reference web design guide provided (autism-web-design.html). Each rule below is implemented in good/index.html with an inline code comment ([R1] through [R20]).

Rule Guideline How it is implemented in the good site Source
R1 Muted, low-saturation colour palette All colours are defined as CSS variables with deliberately low saturation: sage green (#5a7a5a), warm cream (#f5f2eb), dusty blue (#3a5a8a). No pure red, yellow, or neon hues are used anywhere on the site. Lecture slide: "Identifying Sensory Barriers" — digital platforms with bright colours cause sensory overload
R2 Off-white background, not pure white Background is #f5f2eb — a warm cream. Pure white (#ffffff) creates glare and visual discomfort. The card background is #faf8f3. Reference site checklist: "Off-white background"
R3 Body text ≥ 16–18px, line-height ≥ 1.5 Default font size is 18px (--fs-base: 18px). Line-height is set to 1.75 (--lh: 1.75). Users can increase size to 21px or 24px via the toolbar. Reference site checklist: "Body 16–18px, line-height 1.5+"
R4 Accessible, readable fonts Body uses DM Sans — a clean humanist sans-serif. Headings use Literata — a serif designed for long-form reading. Both fonts have clear letterforms and open spacing. Reference site: uses Atkinson Hyperlegible (accessibility-first font)
R5 No automatic animations There are zero CSS keyframe animations or JavaScript-driven transitions that play without user action. The only transitions are 0.2s hover and dark-mode swaps — short, subtle, and user-triggered. The site also respects @media (prefers-reduced-motion: reduce) to disable even those. Reference site checklist: "prefers-reduced-motion honored"
R6 No autoplay audio or video No <audio autoplay>, no <video autoplay>, no embedded media of any kind on the page. The lecture notes identify unexpected sounds as a major auditory barrier. Lecture slide: "Auditory Sensitivities — distress from sudden sounds"
R7 Predictable, consistent navigation The navigation bar is sticky at the top of the page. It has the same position, same links, and same visual style on every section. The footer also contains consistent links. Users always know where to find navigation. Reference site checklist: "Predictable navigation"
R8 Icons always paired with text labels Every interactive element that uses an icon also has a visible text label. CTA buttons show an icon + the words "Browse articles". Read-more links say "Read full article" + arrow icon. Nav links are text only. The toolbar buttons show both icon and word. Reference site checklist: "Icons paired with text labels"
R9 Colour is never the only signal Category tags use an icon + colour + text (e.g. "Nature" tag has a small icon AND the word). The accent border on cards uses both colour (green left border) and position. No information is conveyed by colour alone. Reference site checklist: "Color not the only signal"
R10 Dark mode toggle (persistent) A clearly labelled "Dark mode" button in the accessibility toolbar switches the entire site to a dark palette via CSS variables. The setting is saved to localStorage and restored on next visit. Reference site checklist: "Light / dark mode toggle — visible, persistent"
R11 Text size controls (persistent) Four text-size buttons (Small / Default / Large / Larger) let the user choose 16px, 18px, 21px, or 24px. Current selection is highlighted with aria-pressed="true". Setting saved to localStorage. Reference site checklist: "Text scaling — full functionality at 200% zoom"
R12 Reduce motion toggle A "Reduce motion" button in the toolbar adds the class reduce-motion to <body>, which sets transition: none and animation: none on all elements. This goes beyond relying solely on the OS system preference. Reference site checklist: "Reduce motion toggle — beyond just system pref"
R13 Plain, literal language — no idioms or sarcasm All page copy is written in plain, direct English. Example: "A quiet space for thoughtful reading. The text is clear. The layout is simple. There are no distractions." No idioms ("don't miss the boat"), no sarcasm, no ambiguous phrases. Reference site checklist: "No idioms or sarcasm" + Lecture: autistic communication is direct and literal
R14 Visible keyboard focus indicators All interactive elements show a 3px solid blue outline on :focus-visible. The blue (#3a5a8a) is distinct from the site's green accent colour, ensuring it is always visible regardless of the element's background. WCAG 2.1 / Reference site: keyboard navigation
R15 No time limits, pop-ups, or surprise interruptions There are zero pop-ups, modal dialogs, alert boxes, notification banners, or countdown timers anywhere on the page. The site is fully static and predictable from load to close. Reference site checklist: "No time limits or extendable"
R16 Single-column layout Main content uses a single centred column with max-width: 720px. Articles are stacked vertically. There are no complex multi-column grids that force users to track multiple reading directions simultaneously. Reference site checklist: "Single-column forms" + Lecture: spatial layout clarity
R17 Adequate white space — no clutter Generous spacing system: --space-lg: 2rem, --space-xl: 3rem. Cards have internal padding of 1.25rem. Sections are separated by 3rem. The page never feels dense or overwhelming. Lecture slide: "Cluttered designs increase sensory overload"
R18 Contrast ≥ 4.5:1 Main text (#2a2620) on background (#f5f2eb) achieves approximately 11:1 contrast. Muted text (#4a4540) on the same background achieves approximately 6:1. All combinations exceed the WCAG AA minimum of 4.5:1. Reference site checklist: "Contrast 4.5:1 minimum"
R19 Skip-to-main-content link A visually hidden "Skip to main content" link is the first element in the DOM. It becomes visible on focus. This allows keyboard users to jump past the navigation bar directly to the article content. WCAG 2.1 / Reference site: keyboard navigation
R20 No hover-only interactive features All functionality works with keyboard and touch. Card hover states add a shadow — a purely cosmetic enhancement. No critical information or functionality is hidden behind hover-only states. Reference site checklist: "No hover-only features"

Bad site — rules broken

The bad site (bad/index.html) is a deliberately dysfunctional e-commerce page. Each violation is annotated with [V1]–[V20] in the HTML source code.

Rule Guideline broken How it is broken in the bad site Effect on autistic users
V1 Muted palette (broken) Pure red (#ff0000), lime (#00ff00), magenta (#ff00ff), cyan (#00ffff), yellow (#ffff00) — maximum saturation. Colours are used simultaneously with no visual hierarchy. Visual hypersensitivity overload; difficulty focusing; distress
V2 Off-white background (broken) Pure white (#ffffff) background with a red/green diagonal stripe pattern (repeating-linear-gradient) tiled across the main content area. Glare on pure white; busy pattern prevents reading
V3 Readable font size (broken) Body font size is 9–11px. Line-height is 1.0–1.1. One block of text uses 8px font. Some form labels use no font size larger than 9px. Impossible to read comfortably; causes eye strain and cognitive overload
V4 Readable fonts (broken) All text uses font-family: 'Comic Sans MS', 'Chalkboard SE', cursive — fonts with irregular letterforms that are not designed for accessibility or extended reading. Harder to decode letter shapes; adds processing load
V5 No automatic animations (broken) The page uses 10+ simultaneous CSS keyframe animations: flashColors (rapid background colour cycling), spin (continuous rotation), bounce (jumping elements), shake, pulse, rainbow (text colour cycling), blink. All play automatically and continuously with no off switch. Sensory overload; triggering for vestibular and visual hypersensitivity; panic
V6 No autoplay audio (broken) An <audio autoplay loop> element is placed in the page. An event listener also attempts to play audio on every user click, so silencing it is not straightforward. Sudden unexpected sound causes distress; auditory hypersensitivity
V7 Consistent navigation (broken) There are two separate navigation bars. The first appears at the top-right inside the header. The second appears mid-page at an unrelated position. Both use different icons and layouts. No consistency or predictability. Disorientation; inability to build a mental model of the page
V8 Icons with text labels (broken) Both navigation bars use icon-only buttons (🏠 📦 🛒 etc.) with empty title="" attributes. The pop-up close button is a bare "✕" symbol. The form submit button is just "✓". No visible text labels anywhere. User cannot know what buttons do; increased anxiety and errors
V9 Colour as only signal (broken) Three coloured squares (red, green, yellow) are placed in the middle of the page as "status indicators" with no accompanying text, icon, or tooltip. Star ratings are shown in red with no accessible label. Form validation uses coloured squares only. Colour-blind users and those who need explicit labels cannot interpret meaning
V10 User controls (broken) There is no dark mode, no text size control, no reduce motion toggle, and no accessibility toolbar of any kind. The user has zero ability to customise the experience. No way to reduce sensory input; trapped in an overwhelming environment
V11 No surprise pop-ups (broken) A full-screen pop-up with a shaking animation and flashing rainbow text appears 3 seconds after page load. Clicking outside does not close it. The close button has no accessible label. It also contains a countdown (rule V20). Surprise interruptions cause acute anxiety; unpredictability is extremely distressing
V12 No moving/scrolling text (broken) A marquee-style scrolling text bar cycles continuously across the page: "DON'T MISS THE BOAT! ACT NOW BEFORE IT'S TOO LATE!..." The user cannot pause or stop it. Moving text is impossible to ignore; visual distraction prevents focusing on content
V13 No autoplay video/GIF (broken) Two "fake video" elements simulate auto-playing video with rapid CSS colour cycling animations. They carry labels "VIDEO PLAYING AUTOMATICALLY — CANNOT STOP" and "LIVE SALE NOW". Movement in peripheral vision is hard to filter out; triggers sensory seeking/avoidance
V14 Consistent layout (broken) Section 1 uses a 5-column grid. Section 2 uses a 3-column (20/60/20) grid. Section 3 uses a 7-column grid. Section 4 uses an arbitrary flexbox row. No layout system or visual consistency. Impossible to build a mental map of the page; exhausting to navigate
V15 Adequate white space (broken) Most elements have padding: 2–4px and margin: 1–2px. Seventeen items are packed into one card. One column contains 14 stacked single-word lines with no spacing. Text blocks have line-height: 1.0. Dense layouts cause visual overload; difficult to identify where to look
V16 Plain language (broken) The page is full of idioms: "Don't miss the boat", "bite the bullet", "ball is in your court", "hit the ground running", "let the cat out of the bag", "barking up the wrong tree". The dismiss button reads "No thanks, I hate savings" — guilt-tripping language. Idioms are often interpreted literally by autistic users; causes confusion and distress
V17 Visible focus indicators (broken) * { outline: none !important; } removes all focus indicators from every element on the page. Keyboard users receive zero visual feedback when navigating. Keyboard-dependent users cannot navigate the page at all
V18 No flashing content (broken) The header flashes through 10 hues at 0.4-second intervals (~2.5Hz — above the 3-flash/second danger threshold). Three separate elements cycle background colours at 0.2–0.5s intervals. The blink animation toggles visibility at 0.5s. Photosensitive seizure risk; extreme visual distress; fight-or-flight response
V19 Skip navigation link (broken) There is no skip link. Keyboard users must tab through every one of the 14+ animated navigation icons, the countdown timer, and all other elements before reaching any content. The navigation itself is unpredictable (see V7). Keyboard users are trapped in an exhausting tab sequence
V20 No time pressure (broken) A prominent countdown timer at the top of the page counts down from 9:59 at an accelerated rate. The pop-up contains a 10-second countdown before auto-closing. Text "ONLY 2 ITEMS LEFT — BUY NOW OR CRY LATER" creates additional pressure. Time pressure triggers anxiety; autistic users often need more processing time

How to host on GitHub Pages

GitHub Pages is free and requires only a GitHub account. The two sites can be hosted in the same repository as subfolders, or in separate repositories.

Option A — One repository, two subfolders (recommended)

1

Create a new GitHub repository

Go to github.com/new. Name it e.g. autism-web-design. Set it to Public. Do not add a README yet.

2

Create the folder structure

Your repository should look like this:

autism-web-design/
  index.html  ← this explanation page
  good/
    index.html  ← autism-friendly site
  bad/
    index.html  ← autism-unfriendly site

3

Upload files via the GitHub web interface

Open your repository on GitHub. Click Add file → Upload files. Upload index.html, then create the good and bad subdirectories by naming files good/index.html and bad/index.html when uploading.

4

Enable GitHub Pages

Go to your repository → Settings → Pages. Under "Branch", select main and folder / (root). Click Save.

5

Your live URLs

After about 1–2 minutes, your sites will be live at:
https://YOUR-USERNAME.github.io/autism-web-design/ (this page)
https://YOUR-USERNAME.github.io/autism-web-design/good/
https://YOUR-USERNAME.github.io/autism-web-design/bad/

6

Take screenshots

Open each URL in a browser. Press F12 to open DevTools, then press Ctrl + Shift + P (or Cmd + Shift + P on Mac) and type "Capture full size screenshot" to save a full-page PNG. Submit the screenshots alongside the live links.

Option B — Two separate repositories

Repeat the steps above twice — once for the good site (name it leafwell-good) and once for the bad site (name it leafwell-bad). URLs will be YOUR-USERNAME.github.io/leafwell-good and …/leafwell-bad.

Summary of design decisions

The two sites share the same subject matter (a reading platform) to make the contrast purely about design choices rather than content. The good site implements all 20 rules from the lecture materials and the reference guide, while the bad site deliberately violates each one in a documentable and explainable way.

The key lesson demonstrated is that autism-friendly design is not a checklist of visual adjustments — it is a fundamental commitment to predictability, user control, and the reduction of unnecessary sensory input. As the reference slides state: "Calm design is good design."
